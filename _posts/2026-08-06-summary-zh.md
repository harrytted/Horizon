## [Deno 发布 Celld：自托管分布式持久对象](https://github.com/denoland/celld) ⭐️ 8.0/10

Deno 发布了 Celld，这是一个自托管的分布式持久对象运行时，可将数据复制到兼容 S3 的存储。该项目已在 GitHub 上提供，成为持久对象模型的与提供商无关的实现。 这很重要，因为由 Cloudflare Workers 推广的持久对象抽象长期以来主要局限于单一云厂商。Celld 为开发者提供了自托管选项，减少了对供应商的依赖，并允许在他们自己的基础设施上构建有状态的无服务器应用。 在 Celld 的模型中，每个持久对象按名称寻址，并由其自身的 SQLite 数据库支持，该数据库会复制到用户拥有的兼容 S3 的存储桶中。该设计沿用了 Cloudflare 引入的单线程对象模型，但运行在自托管环境中。

hackernews · calvinfo · 8月5日 16:50 · [社区讨论](https://news.ycombinator.com/item?id=49185430)

**背景**: 持久对象是一种云计算概念，其中每个对象是拥有自己持久存储的单线程计算单元，按名称寻址。Cloudflare Workers 是最著名的实现，Cloudflare 还将其运行时以 workerd 开源。Celld 旨在特定云之外提供相同的抽象，使用兼容 S3 的存储进行复制。

## [LLMs 无法跳跃：论文挑战 AI 的科学推理能力](https://openreview.net/challenge?redirect=%2Fforum%3Fid%3DklU4737opt) ⭐️ 8.0/10

一篇题为《LLMs 无法跳跃》的立场论文发布在 OpenReview 上，认为大型语言模型在需要直觉跳跃的推理任务（尤其是科学发现）中存在根本性局限。该论文已引发广泛讨论，在平台上收到 171 条评论。 该论文的重要性在于它对 LLM 能够加速科学突破的乐观叙事提出了质疑，这是 AI 社区日益关注的话题。其高参与度反映了人们对 LLM 真实推理能力的不确定性。 该论文作者为 Tom Zahavy，他利用爱因斯坦推导洛伦兹变换等例子来论证 LLM 依赖现有文本叙述而非做出真正的概念飞跃。然而，一些批评者质疑其缺乏定量证据以及历史解读的准确性。

hackernews · theanonymousone · 8月5日 11:01 · [社区讨论](https://news.ycombinator.com/item?id=49181083)

**背景**: 大型语言模型通过预测序列中的下一个词元进行训练，这使它们能够生成流畅且看似合理的文本，但关于它们能否进行真正推理或具有创造性洞察力的问题仍存争议。AI 研究中的立场论文旨在呈现作者的观点以引发讨论，而非提供实证结果，当涉及紧迫话题时往往会引发大量社区反馈。《LLMs 无法跳跃》一文正是对 AI 局限性（尤其是在科学研究等高风险领域）这一持续辩论的贡献。

**社区讨论**: 评论意见不一：有人同意语言是一种有损编码，限制了 LLM 的理解；也有人批评论文缺乏定量证据并过于简化历史事件。作者通过社交媒体澄清，论文并非声称 LLM 永远无法为科学做出贡献，而是强调某些特定局限。讨论中还涉及一些假设性实验，例如用 1990 年前的文本训练 LLM，以检验其能否重新创造出现代发现。

## [Webhooks 的困境：用流式 HTTP 订阅作更可靠的替代方案](https://weli.dev/blog/the-valley-of-webhooks/) ⭐️ 8.0/10

这篇文章分析了使用 Webhook 进行状态同步的实际问题，并提出了一种基于流式 HTTP 的订阅协议作为更可靠的替代方案；有评论者指出该方案与 IETF 的 Braid-HTTP Subscriptions 草案非常相似。 Webhook 被广泛用于实时事件推送，但在状态同步中的可靠性问题影响了许多 API 使用者。标准化的流式 HTTP 订阅方式有望提高数据一致性，并降低整个行业的集成复杂度。 该方案使用带有 'Prefer: stream' 头的 GET 请求来维持持久连接，以解决签名、去重、缓冲、引导和基于 cron 的轮询等问题。但有评论者指出，对于低频事件，持久连接可能效率低下，并且可能触及 CDN 的连接数限制。

hackernews · weli · 8月5日 15:22 · [社区讨论](https://news.ycombinator.com/item?id=49184216)

**背景**: Webhook 是用户自定义的 HTTP 回调，用于在事件发生时提供实时通知，但存在投递失败、顺序和幂等性等问题。状态同步是分布式系统中的一个难题，多个节点需要保持一致的数据视图；HTTP 流式传输则支持通过持久连接增量交付响应数据，这与 HLS 或 DASH 等媒体流协议不同。

## [Monodratic：学习式乘积哈希路由的稀疏注意力](https://www.reddit.com/r/MachineLearning/comments/1vg3jda/monodratic_learned_producthash_routing_for_sparse/) ⭐️ 7.0/10

Monodratic 是一种使用学习式乘积哈希路由的稀疏因果注意力架构，在关联回忆任务上以仅两个远程块实现了 99.35%的平均准确率，远超未训练路由（425/768）和仅局部注意力（151/768）。该实现以可移植的 PyTorch 代码发布，并附有证明论文和复现代码。 这表明学习式稀疏路由能够在保持高准确率的同时大幅降低注意力计算成本，可能为长上下文模型提供固定的注意力预算方案。它也挑战了稀疏注意力需要手工设计模式的常见假设，为高效 Transformer 提供了一种数据驱动的替代方案。 该路由从 5 个符合条件的远程块中选择 2 个，通过乘积探针重排候选块，并在精确因果 softmax 之前始终加入保证的局部块。实验显示与独立密集掩码 oracle 的最大绝对误差为 1.43e-6；在 4,096 到 32,768 个 token 下，CPU 路由实现的拟合时间指数为 0.993。局限：仅进行合成实验，无融合内核，且未声称自然语言质量或部署速度。

**背景**: 因果注意力是 GPT 等自回归 Transformer 使用的一种机制，只允许每个 token 关注之前的 token，因此计算成本随序列长度呈二次方增长。稀疏注意力通过限制每个查询只关注少量相关键（通常使用固定模式或哈希）来近似全量注意力。RoPE（旋转位置编码）通过旋转嵌入来编码 token 位置，Monodratic 利用它来帮助查询路由到相关的源块。关联回忆（associative recall）是 LLM 的关键能力之一，测试模型能否根据提示检索关联值，例如找到与某个 token 关联的另一 token。

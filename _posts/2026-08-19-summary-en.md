## [Mojo Programming Language Open Sourced Under Apache 2.0](https://simonwillison.net/2026/Aug/18/mojo-is-now-open-source/) ⭐️ 9.0/10

On August 18, 2026, Modular open-sourced the Mojo programming language by releasing its compiler and toolchain under the Apache 2.0 license. This follows last week's Mojo 1.0 release and fulfills a promise made since May 2023. Mojo sits at the intersection of Python simplicity and high-performance AI/ML computing, and open-sourcing it enables broader community adoption, contribution, and trust. This could accelerate the development of GPU programming tools and expand Mojo's ecosystem beyond a single vendor. Mojo was originally planned as a superset of Python, but that goal was changed around August 2025; today it is an independent language optimized for GPU programming with Python-inspired syntax. The compiler is built on the MLIR framework, enabling it to target CPUs, GPUs, TPUs and other accelerators.

rss · Simon Willison · Aug 18, 21:39

**Background**: Mojo is a systems programming language developed by Modular Inc., combining Rust-inspired semantics such as static typing and a borrow checker with a Python-like syntax. It was launched in 2023 with the goal of being a Python superset to bootstrap its ecosystem, but that plan was later abandoned or postponed, and Mojo 1.0 was released in August 2026. Because Mojo builds on the Multi-Level Intermediate Representation (MLIR) framework, it can generate highly optimized code for diverse hardware, making it well suited for AI workloads that need more performance than Python can offer.

Turbovec is a new Rust vector index with Python bindings, implementing Google Research's TurboQuant algorithm. It achieves near-optimal quantization without a training phase, offering massive compression for memory-efficient vector search. This makes state-of-the-art vector quantization accessible to developers, enabling large-scale search and RAG applications to run on local or resource-constrained hardware. It also strengthens Rust's position in the AI data infrastructure ecosystem. Built on TurboQuant, a data-oblivious quantizer with no separate training phase, turbovec reportedly uses around 4GB for 10 million documents. Community members have requested WASM compilation for browser extensions and SQLite bindings, and noted the README could be more human-friendly.

hackernews · fittingopposite · Aug 18, 18:07 · [Discussion](https://news.ycombinator.com/item?id=49349898)

**Background**: Vector search indexes high-dimensional embeddings, whose memory footprint grows rapidly with corpus size. Quantization compresses these vectors, but traditional techniques like product quantization often require training and can hurt recall. TurboQuant is a 2025 Google Research algorithm (to be presented at ICLR 2026) that achieves near-optimal distortion with no training, dramatically reducing memory while maintaining retrieval quality.

## [Quantized Diffusion Model Runs on 264KB RAM Microcontroller](https://www.reddit.com/r/MachineLearning/comments/1vrk7t5/trained_an_diffusion_model_that_runs_on_264kb_of/) ⭐️ 7.0/10

A developer trained a heavily quantized diffusion model that generates 32x32 pixel images on a Shrike lite board with only 264KB of SRAM. The project also tested two parallel INT8 multiply-accumulate (MAC) engines on the onboard FPGA, but they ran slower than the MCU-only version (220s vs 70s per image) due to an I/O memory wall. This demonstrates that generative diffusion models can be pushed onto extremely resource-constrained edge hardware, which is significant for embedded AI and low-power applications. The performance trade-off with FPGA acceleration offers practical lessons for optimizing model inference when memory bandwidth is limited. The model is a diffusion model for 32x32 images with heavy quantization, running on the RP2040 MCU of the Shrike lite board. The FPGA-based parallel MAC engines use INT8 arithmetic with 16-bit accumulation, but the high number of I/O operations created a memory wall that made the parallel approach about three times slower than the MCU-only path.

reddit · r/MachineLearning · /u/PandaBean18 · Aug 18, 09:26

**Background**: Diffusion models are a class of generative models that generate data by progressively denoising random noise. Running them on edge devices usually requires aggressive quantization, which reduces the number of bits used to represent weights and activations. The Shrike lite is a low-cost open-source board that combines an RP2040 microcontroller with a small 1120-LUT FPGA, providing a platform for experimenting with MCU+FPGA acceleration.
